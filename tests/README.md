# 测试流程

先跑自动的,再开网页手动看。顺序不要反 —— 第 2 步能把"相机/推流本身坏了"和
"参数调了但没效果"这两类问题分开,省掉大量瞎猜。

```bash
source venv/bin/activate      # 每一步都先激活
```

| 文件 | 用途 | 需要浏览器 |
|---|---|---|
| `test_smoke.py` | 驱动 + 推流契约自检,28 项 | 否 |
| `test_camera_console.py` | 参数 / 画幅 / 推流 手动调试台 | 是 |
| `test_camera_diagnosis.py` | 相机完全出不来图时的硬件分层排查 | 否 |
| `test_rectangle_detect.py` | 矩形检测算法调参 | 是 |
| `test_tracking_test.py` | 13 参数跟踪 + 误差分析 | 是 |

## 第 1 步 · 自动自检(约 40 秒)

```bash
python tests/test_smoke.py
```

**期望:`结果: 28/28 通过`,退出码 0。**

中间会打印两条 traceback(非法模式号、注入的 provider 异常)—— 这是**故意注入的**,
用来验证错误路径不会把程序带崩,看到它们是正常的。

参考实测值(IMX219,室内):

| 检查项 | 正常范围 |
|---|---|
| 采集 FPS | 20 ~ 30(默认配置受 3280×2464 模式限制在 21fps 上限) |
| 帧格式 | `(480, 640, 3) uint8` |
| ExposureTime 回读 | 设 8000 → 实测 7996 左右,误差 < 500us |
| FOV 对比 | 全画幅 100% → 裁切模式 15% |
| `stop()` 耗时 | < 0.3s |

**任何一项 FAIL 就先别开网页**,按下面"故障对照"处理。

## 第 2 步 · 网页手动验证

```bash
python tests/test_camera_console.py
# 从你的电脑/手机浏览器打开 http://<树莓派IP>:5000
```

树莓派 IP 用 `hostname -I` 查。左侧面板每秒刷新一次。

### 2.1 推流是否正常

看左上"推流"区:

- **推流 FPS** 和**采集 FPS** 都应该在跳动
- 画面流畅无卡顿,右上角绿字显示分辨率和帧率

判读:

| 现象 | 含义 |
|---|---|
| 两个 FPS 都正常 | 推流链路完好 |
| 采集正常、推流掉到个位数 | JPEG 编码或网络是瓶颈,不是相机问题 |
| 两个都停住、帧序号不涨 | 相机采集线程死了 → 回第 1 步 |
| 画面卡成静止但帧序号在涨 | 浏览器端问题,刷新页面 |

### 2.2 曝光 / 增益 —— 有硬件回读,可以铁证

带 `可回读` 标记的两项,拖动后对比"设定值"和"硬件实测":

1. 拖 **ExposureTime** 到 5000 → 1 秒内"硬件实测 ExposureTime"应跟到 ≈5000,画面变暗
2. 拖到 40000 → 实测跟到 ≈40000,画面变亮
3. 拖 **AnalogueGain** 到 8.0 → 实测跟到 8.00,画面变亮且噪点明显增多

**两个数字对不上就是参数没进硬件。**

注意:曝光时间受帧间隔封顶。面板上"帧间隔"显示多少微秒,曝光最多只能设到那个值
附近;想要更长曝光得先切到低帧率的 sensor mode。

### 2.3 亮度 / 对比度 / 饱和度 —— 没有回读,看画面统计

这几项是 ISP 控制项,libcamera 不返回实测值,所以改用"画面统计"区做客观判断:

| 拖动 | 应该看到 |
|---|---|
| Brightness ↑ | **亮度均值**明显上升(-0.6 → +0.6 可以从个位数拉到 170+) |
| Contrast ↑ | **标准差**上升,画面明暗反差变大 |
| Saturation ↑ / ↓ | **饱和度均值**跟着变,拉到 0 画面变灰度 |
| Sharpness ↑ | 统计值不动,看边缘锐化程度(这项只能肉眼判断) |

数字纹丝不动 = 该参数没生效。

### 2.4 画幅 —— 两个独立的控制,别搞混

面板上是分开的两栏,改的是**完全不同的两件事**:

#### (a) 输出分辨率 —— 改画面尺寸

点"输出分辨率"下面的按钮。**只有这个会让左上角绿字变化。**

实测(视场基本不变,推流帧率随分辨率下降):

| 点击 | 左上角 | FOV | 推流 FPS |
|---|---|---|---|
| 320×240 | 320x240 | 99.8% | ~90 |
| 640×480 | 640x480 | 99.8% | ~80 |
| 1280×720 | 1280x720 | 74.9% | ~62 |
| 1640×1232 | 1640x1232 | 100% | ~41 |

1280×720 的 FOV 掉到 75% 是正常的 —— 传感器是 4:3,输出 16:9 要裁掉上下。

#### (b) 传感器模式 —— 改视场和采集帧率

点"传感器模式"下面的按钮(格式 `序号: 宽x高 位深 @帧率`)。
**画面尺寸不会变**,变的是 ScalerCrop:

| 模式 | ScalerCrop | 占传感器面积 | 现象 |
|---|---|---|---|
| 1 / 3 / 5 / 7 | `0, 0, 3280, 2464` | ≈100% | 全视场,广角 |
| 0 / 4 | `1000, 752, 1280, 960` | ≈15% | 2× 中心裁切,画面像被"放大" |
| 2 / 6 | `680, 692, 1920, 1080` | ≈26% | 1080p 裁切 |

**判断切模式是否生效要看 ScalerCrop / 占传感器面积,不要看分辨率。**
点 mode 0 → FOV 掉到 15.2%,点 mode 1 → 回到 99.8%,尺寸全程 640×480 不动。

默认已锁全画幅中最快的模式(`Camera(full_fov=True)` → IMX219 选 1640×1232 @81fps,
而不是 3280×2464 @21fps)。

#### (c) 想要高帧率怎么配

**帧率的第一瓶颈通常是曝光时间,不是分辨率也不是模式** —— `帧间隔 >= 曝光时间`,
默认 30000us 就把上限锁死在 33fps 了。实测(640×480 全画幅):

| 配置 | FOV | 采集帧率 |
|---|---|---|
| 默认(曝光 30000us) | 99.8% | 33 fps |
| **曝光降到 5000us** | 99.8% | **81 fps** |
| `full_fov=False` + 曝光 5000us | 15.2% | 197 fps |

竞赛推荐配置(全画幅 640×480 高帧率):

```python
cam = Camera(output_size=(640, 480))          # full_fov 默认 True
cam.start()
cam.set_params({"AeEnable": False, "ExposureTime": 5000, "AnalogueGain": 8.0})
```

曝光缩短会变暗,用 `AnalogueGain` 补回来(代价是噪点)。光线不足就只能在帧率和
噪点之间取舍。要 197fps 那档必须放弃全画幅(2× 裁切),视野只剩 15%,一般不划算。

翻转:点 `↕ V-Flip` / `↔ H-Flip`,画面立刻翻转,按钮变绿表示已开启。

### 2.5 自动曝光

1. 点 **开启 AE** → 用手遮挡镜头再移开,实测 ExposureTime 应自动来回变化
2. 点 **锁死当前值** → 再遮挡镜头,实测值应该**纹丝不动**(已锁死)
3. 此后拖动 ExposureTime 滑条仍然有效(手动模式)

### 2.6 拍照

点 **📷 拍照存盘** → "最近存盘"出现 `console_时间戳.jpg`,
文件落在 `samples/` 下,用 `ls -lt samples/ | head` 确认。

退出:终端 `Ctrl-C`。

## 故障对照

| 症状 | 处理 |
|---|---|
| `ModuleNotFoundError: No module named 'src'` | 没在项目根目录跑,`cd ~/workspace` |
| 完全出不来图 / `Picamera2 error` | `python tests/test_camera_diagnosis.py`,按它给的分层结论查 |
| `Address already in use` | 上一个测试没退干净:`pkill -f test_` 后重试 |
| 网页打不开 | 用 `hostname -I` 确认 IP;确认电脑和树莓派同一局域网 |
| 本机 `curl 127.0.0.1:5000` 返回 502 | 你开着 HTTP 代理。`curl --noproxy '*'` 或先 `unset HTTP_PROXY HTTPS_PROXY` |
| 参数拖了实测值不跟 | AE 还开着会覆盖曝光/增益;控制台里拖曝光会自动关 AE,直接调 API 则要先发 `AeEnable: False` |
| 切模式后画面卡住 2 秒 | 正常,`switch_sensor_mode` 要停流→重配→重启 |
| 画面变"慢倍速"、按钮点了没反应 | 曾经的 bug(metadata 请求抢帧缓冲),已修。若再出现,先看采集 FPS:掉到个位数说明又有人在直接调 `capture_metadata()`,必须走 `cam.get_metadata()` |
| `Method Not Allowed` | 曾经的 bug(首页只收 GET,刷新时浏览器可能发 POST),已修 |
| 高分辨率下推流很卡 | 先看推流 FPS 是否远高于采集 FPS —— 那是在重复编码同一帧,`frame_provider` 要按 `cam.frame_id` 去重 |
